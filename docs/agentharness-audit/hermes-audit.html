Priority improvements

Top 3 gaps ranked by distance from 9.5. Each one is a specific source change, not a direction.

  • 1 gap −0.5
    P02 — Cache-Stable System Prompt
    Add HERMES_DEFER_TOOL_SCHEMAS=1 flag to suppress full schemas from the API tools parameter. When active, inject a compact name+description index into the stable prompt tier; tool_search (already present) returns full schemas on demand. The ALWAYS_LOADED_TOOLS pattern is in place — this closes the last gap in agent/agent_init.py:914-931.
  • 2 gap −0.5
    P10 — Deferred Context Loading
    Sandbox backend unavailability now emits a logger.warning() (added in this cycle) but still degrades to unsandboxed execution silently after the warning. Structural enforcement — requiring sandbox or explicit opt-out before any shell invocation — would close this gap. Add a HERMES_SANDBOX_REQUIRE=1 mode that raises SandboxUnavailableError instead of degrading.
  • 3 gap −0.5
    P12 — Mechanical Learning Loop
    Pre-turn and 413-recovery compaction are solid. The remaining gap is true mid-turn streaming compaction: catching context overflow during a streaming response (not just on 413 error) and restarting the stream with compacted history. Implement a StreamingCompactor wrapper in agent/conversation_loop.py that catches ContextLimitError mid-stream, compacts, and retries — matching Codex compact.rs stage-2 behavior.

P12 Compaction Under Pressure
Found
agent/conversation_loop.py:476-541 — pre-turn preflight compaction at 85% of the model's context threshold (resolved via agent.context_compressor.threshold_tokens). conversation_loop.py:2359-2587 — 413 error handler with auto-recompaction and retry. conversation_loop.py:34-40 — CompactionLoopError raised after max consecutive compressions without progress. agent/compaction_analytics.py — per-event JSONL to ~/.hermes/compaction.jsonl with trigger/strategy/tokens_before/after/reduction_pct. providers/base.py:78 — ProviderProfile.default_context_length field added this cycle; agent_init.py:1379-1389 — wired as provider-level fallback in compressor init chain. Missing
No true mid-turn streaming compaction. The 413 handler catches the error after the streaming response fails; it does not intercept the stream mid-flight and recompact. Codex compact.rs stage-2 catches ContextLimitError during async for chunk in stream, recompacts, and restarts the stream. Hermes recovers from 413 but does not recover from mid-stream truncation that doesn't produce an error code.
To reach 9.5
In agent/conversation_loop.py, wrap the streaming response iterator in a StreamingCompactor context manager. On ContextLimitError mid-stream, compact messages, restart the stream, and continue yielding chunks. This requires the streaming path to be restartable — extract the API call into a _call_model(messages) helper that can be retried with compacted messages.
