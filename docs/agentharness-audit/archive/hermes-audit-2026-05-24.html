Priority Improvements

Ranked by gap to 9.5 target. Equal weights.

  • 1 gap −1.0
    P02 — Deferred Context Loading

    Add a deferred schema registry in toolsets.py so full JSON schemas are served by tool_search on demand rather than injected wholesale via the API tools parameter on every call. Introduce a deferred=True flag on tool registrations — core tools (bash, read, write) stay upfront; all others move to the deferred list. This is the highest-leverage token reduction available: ~50K tokens per session for a full toolset.

  • 2 gap −1.0
    P06 — Subagent Delegation

    Add parallel subagent dispatch to agent/subagent.py via asyncio.gather or threading.Thread. Add typed output schemas per specialization (explore → file tree + symbols; review → findings list; plan → ordered steps; execute → status + summary) so callers can rely on consistent return shapes. For execute-type, add optional git worktree isolation so subagents cannot modify the main working directory.

  • 3 gap −1.0
    P10 — Security / Trust Model

    The sandbox infrastructure in agent/sandbox.py is production-quality (bubblewrap on Linux, Seatbelt on macOS) but opt-in. Invert the default: include bwrap in the install script as a standard dependency, warn prominently at startup if no sandbox backend is available, and make HERMES_SANDBOX_DISABLED=1 the explicit opt-out rather than HERMES_SANDBOX_NETWORK_DISABLED=1 being additive. The infrastructure is already complete — only the default needs inverting.

P01 Cache-Stable System Prompt TARGET MET
Found
Three-tier assembly documented in module docstring at agent/system_prompt.py:11–20: stable (identity, tool guidance, model-family guidance, environment hints), context (AGENTS.md and context files), volatile (memory index, USER.md, timestamp line). Date-only timestamp with explicit cache rationale at system_prompt.py:274–280: now.strftime('%A, %B %d, %Y') — "Date-only (not minute-precision) so the system prompt is byte-stable for the full day. Minute-precision changes invalidate prefix-cache KV on every rebuild path. Credit: @iamfoz (PR #20451)." _cached_system_prompt built once on first call at conversation_loop.py:471–472; invalidate_system_prompt() at system_prompt.py:315–323 called only after compression events. Gateway sessions: stored prompt loaded from session DB at conversation_loop.py:464–472 instead of rebuilding, preventing prefix cache invalidation across fresh agent instances. Model/provider in volatile tier; stable tier never changes within a session.
To maintain 9.5+
Guard against future regressions by adding a test that asserts build_system_prompt_parts(agent)["stable"] returns byte-identical output on two consecutive calls within the same session. Any new stable-tier addition (e.g., new guidance constant) must go through this test before merging.
Canonical Architecture — Hermes
Pattern: Three-tier (stable / context / volatile). Every byte before the volatile tier is identical across all turns in a session. Date-only timestamp. Prompt cached on init, invalidated only after compression.
Anti-pattern: Minute-precision timestamp or per-turn rebuild — busts prefix cache, pays full input token cost every turn.
Rationale: LLM prefix caches hash the prefix bytes. Identical prefix = cache hit = ~90% cost reduction on input tokens and ~50% latency reduction.
Winner: Hermes agent/system_prompt.py:269–280 · conversation_loop.py:464–472 · system_prompt.py:315–323

P02 Deferred Context Loading
Found
tools/tool_search.py:4: explicit "deferred-loading pattern" comment — allows model to search for tool schemas by query rather than receiving all schemas at once. Memory index at agent/system_prompt.py:252–256: format_index_for_system_prompt("memory") injects compact index (one line per entry) instead of full memory text — "Reduces volatile tier token usage by ~70% while still surfacing what's stored." Full entries available via memory(action='read'). User profile uses same index pattern at system_prompt.py:259. Skills listed with names/descriptions via build_skills_system_prompt — skill bodies not injected wholesale.
Missing
Full tool JSON schemas are injected via the API tools parameter on every call — all active tool schemas sent to the provider upfront. tool_search provides post-hoc discovery but doesn't reduce the API-call token payload. Claude Code's ToolSearch defers schemas entirely: they are absent from both the system prompt and the tools parameter until the model explicitly fetches them.
To reach 9.5
Introduce a deferred=True flag in toolsets.py tool registrations. On agent init, split tools into core (always injected, e.g. bash, read, write, memory, tool_search) and deferred (schema stored in registry, returned by tool_search only). Pass only core tool schemas in the API tools parameter. tool_search(query) already exists — extend it to return full JSON schemas for deferred tools. This closes the gap without changing the model's tool-calling UX.
Canonical Architecture — Claude Code + Hermes
Pattern: Three-layer hierarchy: names only (always) → descriptions (session start, no schemas) → schemas (on demand via tool_search). Model sees layers 1+2 always; fetches layer 3 only when it decides it needs it.
Anti-pattern: All tool schemas in system prompt or API tools parameter upfront — 15,000+ tokens the model won't use for a given task crowds out actual task context.
Rationale: Model needs just enough to decide what to load. A one-line description is sufficient to call tool_search("bash"). The schema doesn't need to be there before that decision.
Winner: Claude Code ToolSearch (deferred schemas) · Hermes tools/tool_search.py:4 · system_prompt.py:254 (memory index pattern)

Missing
Sandbox is opt-in, not default-on. The logic in sandbox.py:91 silently skips sandboxing if bwrap/sandbox-exec is unavailable — which is the case on most fresh installs that haven't explicitly added the dependency. To reach 9.5

Canonical Architecture — Codex + Claude Code

Anti-pattern: Instruction-only safety — "Never run rm -rf." Adversarial prompts, prompt injection via tool results, and context pressure can all cause models to override safety instructions.
Rationale: Threat model has two adversaries: unintentional harm (model misunderstands task) and adversarial injection (malicious file hijacks agent). Instructions handle case 1 partially; structural enforcement (sandbox) handles both cases because it operates outside the model's context.
Winner: Codex codex-rs/AGENTS.md (Seatbelt, CODEX_SANDBOX_NETWORK_DISABLED) · Claude Code settings.json (allowedTools, PreToolUse hook) · Hermes agent/sandbox.py
